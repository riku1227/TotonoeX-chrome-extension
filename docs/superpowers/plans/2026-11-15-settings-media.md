# 設定と画像初期選択

目的：調査済みの直接コピーに個別設定を加え、プロフィールのメディアを画像から開く。
仕様：DESIGN.mdとDOM-RESEARCH.md。本人から作成を依頼済み、同じ作業場所で継続する。

- [x] 実画面で /<profile>/media?filter=photo の画像選択と、動画へ戻るとfilterが消えることを確認。
- [x] chrome.storage.localを使用し、directCopy/imagesFirstを個別に保存。初期値は両方true。初回読込が済むまでは機能を動かさない。
- [x] media入場時のフィルタなしURLをlocation.replaceでphoto付きへ移す。同一プロフィール内の手動動画切替は尊重。別プロフィール・SPA入場・popstateを扱う。
- [x] storageの変更で直接コピーの復元/再挿入を行う。画像設定は変更時に現在画面へ適用でき、オフで勝手に動画へ戻さない。
- [x] 先にブラウザテストを追加し、未実装で失敗することを確認。
- [x] React＋space-ui-designキットでポップアップを実装。保存失敗・読み込み失敗を上に表示。外部フォントは生成物から除去し、外部通信を加えない。
- [x] 実MV3環境でポップアップ操作、設定維持、タブへの即反映、メディアの再入場・手動切替を検証。
- [x] design-lintと390/1280/ポップアップ幅のDOM監査、撮影→目視→修正→再撮影。
- [x] READMEと配布フォルダ・ZIPを0.2.0へ更新し、Craftに結果と限界を記録。

トレードオフ：メディア入場時の補正に一度ページ再読込が入る。X内部コードやメニューの自動クリックに依存しない。既にphoto指定されたリンクは再読込しない。
範囲：直接コピーは今回も日本語ホームの構造に限定。新機能の画像URL指定はプロフィールmediaだけに限定。

結果：17ブラウザsubtest成功（親を含む19/19）。初期URLのphoto指定を設定読込前から記憶する修正により、素早い手動動画切替の上書きを防いだ。独立レビューで配布popupファイル不足を確認し、3ファイルを追加。最終UIは本人の追加指示に従い、全体の?ヘルプを廃止し、各オプションへ説明を併記。
